# 发布计划页 V2：Codex 执行方案

## 1. 目标与边界

本次将现有“一屏式发布表单”改造成移动端分步发布流程，让用户先确定路线和日期，再补充玩法内容，最后预览并确认发布。

- `[CONFIRMED]` 依据用户提供的 6 张连续原型画面实现信息结构、字段、交互和视觉层级。
- `[INFERRED]` 原型没有展示预览页和最终发布反馈；为保证现有业务闭环，补充“预览计划 → 确认发布 → 我的计划”的最后一步。
- `[INFERRED]` 当前项目是本地 Mock 数据架构，没有真实地点检索、图片存储和地图服务；本轮使用本地地点候选、浏览器本地图片预览和本地状态持久化，不引入后端。
- `[TO_CONFIRM]` 后续接入真实服务时，需要确认地图 POI 服务、图片上传服务、图片压缩策略和发布审核机制。

## 3. 页面清单与布局

### P1.1 地点与日期

1. 顶部只保留返回按钮，不再使用“发布计划”通用标题栏。
2. 主标题“你想去哪里？”；搜索框支持输入地点关键词和一键清空。
3. 搜索结果卡片展示缩略图、名称、区域/类型/距离和添加按钮。
4. 已选地点以标签和有序路线卡片双重呈现，最多 3 个。
5. 路线卡片支持删除与调整顺序；第一个地点作为主地点，用于兼容现有活动列表与地图筛选。
6. 日期入口显示“开始日期–结束日期”或已选区间；点击打开 P1.2。
7. 页面底部固定“下一步”；必填未完成时保持禁用视觉，并在用户尝试后显示原因。

### P1.2 日期选择 Sheet

1. 标题“你想去多久？”、时区说明“北京时间 GMT+8”。
2. 提供开始日期、结束日期两个日期控件。
3. 提供“灵活天数”开关；本轮仅记录偏好，不改变日期校验。
4. 结束日期不得早于开始日期；确认后回填 P1.1。

### P1.3 玩法内容

1. 标题“这次准备怎么玩？”和说明“上传照片，和大家分享这次旅行的亮点吧”。
2. 照片必填、最多 3 张；第一张自动成为封面，可删除并重新选择。
3. 行程介绍必填，最大 500 字，实时计数。
4. “更多补充说明（选填）”默认折叠，展开后包含：
   - 交通方式：步行、自驾、地铁、打车、公交（单选）；
   - 预算：免费、50 内、50–100、100+（单选）；
   - 集合方式/地点：文本输入，最大 60 字；
   - 注意事项：怕晒、带水、穿舒服鞋、可带朋友（多选）；
   - 其他补充：文本输入，最大 200 字。
5. 底部固定“预览计划”。

### P1.4 计划预览

1. 展示封面、自动生成标题、路线顺序、日期范围、介绍和已填写的补充信息。
2. 提供“返回修改”和“确认发布”。
3. 发布成功后进入个人中心“我的计划”集合，并可从全局列表继续查看该活动。

### Activity 兼容扩展

保留现有 `locationId/date/dateLabel/category/intensity/capacity`，避免破坏发现、筛选、详情、报名和个人中心；新增字段全部为可选：

```ts
routeStops?: string[];
endDate?: string;
photos?: string[];
transport?: string;
budgetLabel?: string;
meetingPoint?: string;
notices?: string[];
extraNotes?: string;

```

映射规则：首个已选地点映射为 `locationId`；多地点自动归类为“短途旅行”，单个城市地点归类为 “Citywalk”；默认强度“轻松”、容量 4 人、招募状态 `recruiting`。预算标签映射到现有 `budgetMin/budgetMax`，确保旧页面继续可用。

## 5. 状态机

```text
DESTINATION
  ├─ open_date → DATE_SHEET
  ├─ invalid_next → DESTINATION(error)
  └─ valid_next → DETAILS

DATE_SHEET
  ├─ cancel → DESTINATION(previous value)
  └─ confirm_valid → DESTINATION(date saved)

DETAILS
  ├─ toggle_more → DETAILS(collapsed/expanded)
  ├─ invalid_preview → DETAILS(error)
  ├─ back → DESTINATION
  └─ valid_preview → PREVIEW

PREVIEW
  ├─ back → DETAILS
  └─ confirm_publish → PUBLISHING → SUCCESS/MINE
```

说明：页面状态和按钮动作分开管理；每一步只校验本步必填项，避免用户在第一步就看到第二步错误。

## 7. 验收清单

- 可搜索、添加、删除并调整最多 3 个地点，顺序会进入预览和最终活动数据。
- 未选择地点和完整日期范围时不能进入第二步。
- 日期结束值早于开始值时有明确错误。
- 可选择最多 3 张本地图片，首张标记为封面，删除后下一张自动成为封面。
- 介绍空白时不能预览；达到 500 字后不能继续输入。
- 补充说明能独立折叠/展开，各字段选择和计数正确。
- 预览完整呈现已填内容；返回修改不会丢失草稿。
- 确认发布后新活动出现在“我的计划”，旧活动、报名、收藏、个人中心不受影响。
- 390px 手机视口无横向滚动，底部按钮不遮挡最后一个输入项。
- TypeScript 构建通过，线上版本可打开并完成全流程。
